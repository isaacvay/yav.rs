## 0. Verdict en une phrase

Le socle technique est réel et plutôt solide (ça compile, 693 tests passent, aucun `unsafe`, échappement
contextuel correct, crypto sérieuse, `docs/limitations.md` remarquablement honnête), **mais le projet
souffre d'un défaut systémique de synchronisation** : l'arbre de travail (94 chemins sales), la CI,
la documentation et l'artefact publié sur crates.io décrivent quatre projets différents. À cela
s'ajoutent 3 failles de sécurité à traiter en priorité et une sur-promesse massive du README
(~80 fonctionnalités annoncées, dont une part importante de stubs ou de modules mono-processus).

| Domaine | Appréciation |
|---|---|
| Compilation / tests | **Bon** — `cargo check`, `fmt`, `test`, MSRV 1.88 OK |
| CI / reproductibilité | **Insuffisant** — CI rouge, HEAD ≠ travail, métadonnées publiées fausses |
| Sécurité | **Moyen** — bonnes bases, 3 failles élevées (XSS PPR, SSRF Web Push, CSP) |
| Véracité produit | **Faible** — README très sur-vendu, stubs présents dans l'API publique |
| Maintenabilité | **Faible** — 62 % du code est généré, god modules, duplication |
| Documentation | **Contradictoire** — CSRF, MSRV, features, exemples non compilables |

## 2. P0 — Bloquants immédiats

### P0-1 · La CI est rouge
`cargo clippy … -D warnings` échoue sur **2 lints** :
- `crates/yav-core/src/render.rs:289` — `empty line after doc comment` (ligne vide entre `/// …` et `pub const YAV_MICRO_ACTIONS_SCRIPT`).
- `crates/yav-ui/src/overlay.rs:566` — `redundant reference in format! argument` (`&self.id`).

` .github/workflows/ci.yml:39` impose exactement cette commande sur 3 OS.
**Amélioration** : supprimer la ligne vide, retirer le `&`, relancer la CI.

### P0-2 · `HEAD` ne représente pas le projet
`git log -1` = `d65786e6 release: v0.1.5`, mais :
- `HEAD:Cargo.toml` → `rust-version = "1.75"` ; local → `1.88`.
- `HEAD:Cargo.lock` → 259 paquets ; local → 303 (`p256`, `aes-gcm`, `qrcode`, `image` absents de HEAD).
- `HEAD:.github/workflows/ci.yml` → seulement `test` + `audit` ; le job **MSRV** (`ci.yml:47-64`) n'est pas committé.
- **11 fichiers non suivis** : `.env.example`, `CHANGELOG.md`, `CONTRIBUTING.md`, `SECURITY.md`,
  `docs/limitations.md`, les 3 `LICENSE-*` + `NOTICE.md` de `yav-icons`, et surtout
  **`crates/yav-cli/tests/` + `crates/yav-server/tests/`**.

Conséquence : un clone frais de `main` n'a ni les tests d'intégration, ni les licences d'icônes
(pourtant déclarées « shipped » en `CHANGELOG.md:30-32`), ni `docs/limitations.md` (lié depuis `README.md:207`).
**Amélioration** : committer/valider les 94 chemins, puis exiger `git status --porcelain` vide en CI.

### P0-3 · L'artefact publié sur crates.io est désynchronisé
Vérifié sur `https://crates.io/api/v1/crates/yav/0.1.5` (publié le **2026-11-08**) :
- `rust_version: "1.75"` → `cargo install yav-cli` accepte Rust 1.75 puis échoue à la compilation
  (le graphe verrouillé exige 1.88, `docs/limitations.md:165-170`).
- `default = ["classic-icons","minimal-icons","system-icons"]` (les **3 familles**) et **aucune feature `full-icons`**.
  Or `crates/yav/Cargo.toml:29-33` n'active que `classic-icons` et définit `full-icons`.
  `docs/icons.md:21` recommande donc `features = ["full-icons"]`, ce qui **échoue** sur la version publiée.
- `CHANGELOG.md:8` dit encore `## [0.1.5] - Unreleased` pour une version déjà publiée.

**Amélioration** : publier `0.1.6` avec `rust-version = 1.88` et la table de features corrigée,
ajouter un job CI `cargo package --list` + contrôle des métadonnées, passer le CHANGELOG en « released ».

### P0-4 · Contradiction CSRF à fort enjeu sécurité
`CsrfConfig::default()` a `enabled: true` (`middleware.rs:721-727`) et `YavApp::new()` l'utilise
(`app.rs:475`, monté `app.rs:1387`). Mais :
- `SECURITY.md:52` « It is **opt-in** », `:78` « **off** unless you call `YavApp::csrf_protection` »,
- `CONTRIBUTING.md:63` « CSRF is opt-in », `CHANGELOG.md:41` « opt-in »,
- le code se contredit lui-même : `middleware.rs:700` « opt-in, `enabled: false` by default » vs `:717` « enabled by default », `app.rs:399` « opt-in ».
- Seul `docs/limitations.md:107` est exact.

Un lecteur de `SECURITY.md` peut conclure à tort qu'il doit activer la protection, ou au contraire
qu'il est protégé alors qu'il a désactivé le middleware. **Amélioration** : aligner les 6 fichiers sur `enabled: true`.

## 3. P1 — Sécurité (détail, avec sévérité)

### Points forts à préserver
Échappement contextuel `escape_html` / `escape_attribute` / `escape_url` (`yav-core/src/escape.rs:10-129`,
blocage `javascript:`, `vbscript:`, `data:` non média, décodage des caractères de contrôle avant contrôle
du schéma) ; validation des noms de balises/attributs (`render.rs:100-126`) ; rawtext `</script>` neutralisé
(`render.rs:239-263`) ; JWT HS256 en temps constant + `exp`/`nbf`/`iss`/`aud`/leeway (`auth.rs:483+`) ;
PBKDF2 100 000 itérations / sel CSPRNG 16 o ; TOTP constant-time ; sessions AES-256-GCM + HMAC avec
`HttpOnly; SameSite=Lax; Secure` ; CSRF lié à la session et activé par défaut ; WebAuthn ES256 avec
origine/RP ID/challenge/UP/compteur (`passkeys.rs:610-677`) ; durcissement path traversal très complet
(`static_files.rs`, `app.rs`, `image_opt.rs`, `resumable_upload.rs`) ; `DefaultBodyLimit` 2 Mio ;
erreurs non verbeuses en prod ; **aucun secret commité**, aucun `unsafe`.

## 4. P2 — Véracité : écarts entre le README et le code

`README.md:37-117` aligne ~80 puces non qualifiées. `docs/limitations.md` désamorce honnêtement la
plupart d'entre elles, **mais ce fichier n'est pas committé** et le README n'a pas été aligné.

### 4.1 Stubs et données fabriquées exposés comme fonctionnels
- `adapters.rs:104-118` : `EmbeddedDatabaseAdapter::execute` journalise la chaîne SQL et retourne
  `Ok(1)` **sans rien exécuter** ; `query_rows` renvoie `Ok(Vec::new())`. `adapters.rs:226-237` :
  `LocalLlmAdapter` fabrique `"[model] Processed: …"` et 3 flottants dérivés de 2 octets.
  `adapters.rs:275-284` installe ces faux comme `Default` de `ServiceAdapters`. Le test
  `adapters.rs:322-359` **valide le stub** (`Ok(1)`) — cas d'école de « fake success » interdit par `prompt.md:51`.
  → `README.md:106` (« pluggable ServiceAdapters » / Postgres/Redis/S3/OpenAI/SMTP) est une façade.
- `metrics_dashboard.rs:146-157` : télémétrie codée en dur (`1_420_850` requêtes, `342.5` rps, `96.8 %`).
  Le doc comment l'admet, `README.md:85` annonce un dashboard « live » avec `/metrics/dashboard`.
- `email.rs:206-215` : pas de SMTP, écriture dans un `RwLock<Vec<_>>` (`docs/limitations.md:31`).
- `db` : aucun driver ; `yav-cli/src/db_cmd.rs:229,248` appelle `sqlite3`/`psql` externes.
- `security_audit.rs:145-170` : scoring « OWASP A+→F » = heuristique `+25`/`+15` codée en dur.
- `mock_server.rs:109,125,131` : le champ `delay_ms` n'est **jamais consommé** → `README.md:98`
  (« latency and failure rates ») est faux. `MockFaker` = 8 noms / 6 sociétés / dates figées `2026-`.
- `yav/src/lib.rs:1017-1021` : `#[server] create_post` renvoie `"<div>Post Created</div>"` avec `let _ = ctx`.
- `graphql.rs:394-446` : le « GraphiQL 3.x » est un `<textarea>` + `fetch` écrit à la main
  (`README.md:62`, `docs/architecture.md:208-210`, `docs/production.md:459` sont faux ; `docs/limitations.md:41` est exact).

### 4.2 Fonctionnalités sur-vendues
- **10 puces « distribuées »** (`README.md:73,74,82,83,95` : outbox « zero data loss », « cluster-wide
  atomic leases », replica pool multi-région, cache distribué, event sourcing) = `RwLock<HashMap>`
  mono-processus (`docs/limitations.md:24-33`).
- **Endpoints annoncés mais non montés** : `YavApp` ne monte que `/health`, `/healthz`, `/readyz`,
  `/metrics`, `/_yav/image`, `/_yav/og`, `/_yav/vitals` (`app.rs:1113-1139`). Donc `/metrics/dashboard`
  (`README.md:85`), `/graphql` (`:62`), `/mcp` (`:49`), `/_yav/csp-report` (`:66`) n'existent pas par défaut.
- **TVA « 27 états »** (`README.md:63`) : `geo_ip.rs:57-80` ne contient que 19 taux, `_ => 0.0` ;
  13 des 27 pays de `is_eu()` (`:85-113`) ont donc un taux **nul**. Calcul en `f64` (`:135`) malgré
  « penny-accurate ».
- **AVIF / ImagePipeline** (`README.md:75`) : `image_pipeline.rs:13` dit « AVIF encoding is not currently
  supported » et le type `ImagePipeline` n'existe nulle part (seul `WebPEncoder`).
- **PDF signer** (`README.md:78`) : simple tag HMAC, pas une signature PAdES/X.509 (`docs/limitations.md:116`).
- **PPR / fédération** : slots résolus **séquentiellement** (`ppr.rs:7,136,179`) ; `docs/production.md:504`
  parle encore de « parallel slot hydration » alors que `CHANGELOG.md:106` affirme avoir corrigé cette claim.
- **Codegen** : `README.md:160` « from Rust structs » contredit `docs/limitations.md:126-128`.
- **Zero-Allocation VDOM / zero-JS** : `Node::Static` existe, mais 5 runtimes JS monolithiques sont
  embarqués comme chaînes brutes (`yav-core/src/render.rs` = 76 Ko, dont une ligne unique de ~20 Ko ;
  `yav-ui/motion.rs` 38 Ko, `navigation.rs` 37 Ko) — difficile à maintenir, à auditer et à servir sous CSP stricte.

### 4.3 Identifiants / exemples faux
- `AppState` (`README.md:111`, `docs/routing.md:413`) : **introuvable** dans `crates/` ; seul `use_state()` existe.
- **Le seul snippet du README ne compile pas** : `README.md:127` appelle `Motion::new(rsx!{…})` alors que
  `yav-ui/src/motion.rs:248` est `pub fn new() -> Self` → `E0061`. Les enfants passent par `.child(...)`.
  C'est le premier contact utilisateur.
- Comptage de composants incohérent : `README.md:46` « 60+ », `docs/architecture.md:20` « 58 »,
  `crates/yav/src/lib.rs:21,301` « 45+ ».

**Amélioration transversale** : restructurer le README en 3 sections explicites — **Stable** (cœur SSR,
routing, macros, CLI, UI, icons, sécurité de base), **Expérimental / bibliothèque non montée**
(avec renvoi obligatoire à `docs/limitations.md`), **Planifié** — et faire vérifier en CI que chaque
identifiant entre backticks du README possède une définition. Supprimer ou isoler les stubs de
`adapters.rs` derrière une feature `mock-adapters` clairement nommée.

## 5. P3 — Architecture et maintenabilité

### 5.1 God modules et poids mort
- `yav-server/src/app.rs` 2 247 lignes (60 `pub fn`, config + manifeste + routes + CSP + cookies +
  métriques + serveur TCP + 574 lignes de tests).
- `yav-ui/src/input.rs` 2 173, `yav/src/lib.rs` 1 586 (587 lignes de tests **dans la lib**),
  `yav-ui/navigation.rs` 1 328, `motion.rs` 1 300, `yav-cli/new.rs` 1 235,
  `yav-server/middleware.rs` 1 212, `passkeys.rs` 1 117, `session.rs` 1 110, `auth.rs` 1 079.
- `yav-server` = 59 modules fourre-tout (GraphQL, Web Push, VAT, PDF, CRDT…) dont la plupart ne sont
  pas montés (`docs/limitations.md:11-19`).
- **62 % du workspace = littéraux d'icônes** compilés en tableaux statiques, sans tree-shaking par icône.
  `cargo test --workspace` compile même les 3 familles (`docs/limitations.md:91-93`), donc aucune mesure
  de taille binaire publiée n'est représentative.

**Amélioration** : découper `yav-server` en crates *feature-gated* (`yav-server-core`, `yav-auth`,
`yav-enterprise`, …) ; déplacer les catalogues vers `build.rs` + `include_str!` de données compactes
(JSON/JSONC) avec génération à la demande des seules icônes référencées ; publier des mesures de taille.

### 5.2 Surface publique et duplication
- `yav-server/src/lib.rs:481` = **116 `pub use`**, `yav-ui/src/lib.rs:433` = 112, `yav/src/lib.rs:701-999`
  = un prelude de ~300 lignes ; la même surface est maintenue à 4 endroits, avec un
  `pub use …::prelude::*` **de glob dans un glob** (`yav/src/lib.rs:721,983`) : toute collision de nom
  upstream casse les utilisateurs.
- `yav-ui` : 245 `pub struct`, 103 `impl Component`, **683 builders `pub fn …(mut self)`** quasi identiques
  (ex. `button.rs` ↔ `overlay.rs`), scripts JS dupliqués entre `motion.rs` et `navigation.rs`.
- `Node` (enum public 6 variantes), `Element` (4 champs publics), `AttributeValue` publics
  (`yav-core/src/node.rs:12-63`) → toute évolution est un breaking change en `0.1.x`.
  Incohérences : `Element::new` accepte `Cow<'static,str>` mais `attr()` force `String` (d'où `attr_static`) ;
  `IntoAttributeValue for Option<T>` produit `Bool(false)` là où `IntoNode for Option<T>` produit `Node::Empty`.

**Amélioration** : une source canonique de ré-exports, suppression des globs imbriqués, builders générés
par macro/dérive, `#[non_exhaustive]` ou champs privés + accesseurs, `cargo-semver-checks` en CI.

### 5.3 Robustesse
- `Cargo.toml:90` **`panic = "abort"`** en release : le moindre panic de bibliothèque tue le serveur (DoS).
  Panics en code de production : `app.rs:430` (manifeste invalide), `app.rs:1377`, `flash.rs:71`,
  `reload.rs:485`, et surtout **`t_strict!` génère un `panic!` à l'exécution** (`yav-macros/src/lib.rs:339,343`)
  si une clé i18n manque. `expect("Lock poisoned")` dans `outbox.rs`, `event_sourcing.rs`, `rebac.rs`,
  `resilience.rs`, `mock_server.rs` ; `expect("HMAC accepts any key size")` sur le chemin d'auth
  (`auth.rs:242,264,546,760`, `pdf_signer.rs:174`).
- **66 `Result` ignorés en production** : `yav-cli/generate.rs:124,126,133,209,263` (le codegen échoue
  silencieusement à enregistrer un module), `yav-cli/new.rs:1152` (installation Tailwind),
